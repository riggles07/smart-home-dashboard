# Grafana Integration — System Health Tab

How the Node-RED "System Health" tab (REQUIREMENTS_V2 §2) embeds Grafana
observability panels. The Grafana/SERVER side config lives in the
homelab-monitoring repo (`docs/GRAFANA_EMBED.md`); this file documents the
Node-RED side and the prerequisites the dashboard depends on.

## Architecture

```
tablet browser (A7 Lite, 800x1280)
   └── Node-RED UI  http://192.168.4.100:1880/ui/  →  System Health tab
         ├── Health Summary (native widgets)
         │      inject(30s) → "Build health query" → http request →
         │      "Parse health summary" → 2 gauges + 3 text widgets
         │      (Prometheus instant query, one round trip, no iframes)
         └── 6 Grafana panels (ui_template <iframe>s)
                inject(60s) → "Build Grafana embeds" → msg.p.<key>
                → each template's own <script> registers a scope.$watch
                  on msg.p.<key> and sets the iframe src imperatively
                  (d-solo single-panel route)
```

Two data paths on purpose:

- **Native summary widgets** answer "is anything broken?" instantly — the
  Prometheus API call is server-side (from the LXC), cheap, and renders even
  while the Grafana frames are still streaming in. This is the "or API" half
  of the requirement.
- **Grafana panel embeds** carry the high-fidelity history — the actual charts
  a human stares at when something looks wrong.

### The embed URL pattern

```
http://<GRAFANA_URL>/d-solo/<GRAFANA_DASH_UID>/system-health
    ?orgId=1&panelId=<N>&kiosk&theme=dark&from=now-3h&to=now&refresh=30s
```

| Part | Why |
|---|---|
| `/d-solo/<uid>/` | single-panel route: renders ONE panel, no Grafana sidebar/menu. The full `/d/` route carries the whole dashboard chrome inside each frame. |
| `panelId=<N>` | selects the panel. Map: 1 PVE CPU · 2 PVE Memory · 3 PVE Disk I/O · 4 Service Health · 6 ICMP latency · 7 packet loss. |
| `kiosk` | strips the remaining top nav inside the frame. |
| `theme=dark` | matches the dashboard's dark theme — no light flash. |
| `from=now-3h&to=now&refresh=30s` | fixed 3h window; the panel self-refreshes in place (the iframe itself is NOT reloaded — the template script only rewrites `src` when the URL string changes, and the repeating inject always pushes the same URL). |
| `orgId=1` | pins the main org for the anonymous Viewer identity. |

## Grafana-side prerequisites (must be set on the SERVER)

The dashboard DEPENDS on the observability stack's Grafana being configured
for embedding. If these are missing, iframes render **blank**:

| `grafana.ini` setting | Env var (compose) | Value | Why |
|---|---|---|---|
| `security.allow_embedding` | `GF_SECURITY_ALLOW_EMBEDDING` | `true` | without it Grafana sends `X-Frame-Options: deny` → blank frames |
| `auth.anonymous.enabled` | `GF_AUTH_ANONYMOUS_ENABLED` | `true` | frames authenticate as anonymous (no API key in the LXC) |
| `auth.anonymous.org_role` | `GF_AUTH_ANONYMOUS_ORG_ROLE` | `Viewer` | read-only: view dashboards, edit nothing |
| `security.cookie_samesite` | `GF_SECURITY_COOKIE_SAMESITE` | `lax` | default; `strict`/`none`+insecure break the embed session |

These are set in the monitoring stack's compose file
(`stack/docker-compose.yml` in the homelab-monitoring repo) and were applied
live to the Grafana container on 2026-10-11 (recreated over the Docker socket
with the same binds/volume/network; state persisted in the
`monitoring_grafana-data` volume).

The embedded dashboard itself is provisioned there as
`stack/grafana/dashboards/shd-system-health.json` (UID `shd-system-health`):
8 panels — PVE CPU/Memory/Disk-IO timeseries, service-health stat tile, PVE
uptime stat, ICMP latency + packet-loss timeseries, Prometheus targets-up stat.
Its datasource is pinned to uid `homelab-prom` (the co-located Prometheus
service — see the split-host gotcha in the homelab-metrics-stack skill).

## Node-RED side (this repo)

- Flows are generated by `tools/gen_flows.py` (Tab 5 "System Health"); the
  generated file is `flows/05-system-health.flow.json`.
- Groups: **Health Summary** (native), **Proxmox Node Resources** (embeds 1-3),
  **LXC / VM Health** (embed 4), **Network Latency** (embeds 6-7).
- Env vars read by the flows (documented in `deploy/.env.example`):
  - `PROMETHEUS_URL` — base URL for the summary query (default
    `http://192.168.4.145:9090`)
  - `GRAFANA_URL` — base URL for embeds (default `http://192.168.4.145:3001`).
    **Must be reachable from the tablet's browser**, not just from the LXC —
    iframes load client-side.
  - `GRAFANA_DASH_UID` — provisioned dashboard UID (default
    `shd-system-health`)
- iframe styling lives in `css/dashboard.css` (`.shd-embed`,
  `.shd-grafana-frame`): full card width, zero border, contained overscroll.

## Mobile / A7 Lite notes (800×1280)

- 6 iframes × a full Grafana SPA instance is real RAM on a 3GB tablet, so all
  frames are `loading="lazy"` — off-screen panels do not load until scrolled
  near.
- `panelId` frames are width-12 cards (~800px in portrait); the d-solo panel
  reflows to the frame width, no horizontal scroll.
- The 3h `from` window keeps each frame's query payload small enough to render
  in one pass on the tablet's GPU.
- `overscroll-behavior: contain` on the frames stops scroll-chaining jitter
  when a finger drags inside a chart near the frame edge.
- The native summary group renders first (no iframe cost), so the tab is
  never blank-white while Grafana streams in.

## Verifying the integration

```bash
# 1. offline wiring guards (this repo)
python3 tests/test_system_health.py        # or: pytest -q tests/test_system_health.py
python3 tools/validate_flows.py flows/all-flows.flow.json

# 2. live prerequisites
curl -s http://192.168.4.145:3001/api/health                       # Grafana up
curl -s "http://192.168.4.145:3001/api/search?query="             # anonymous Viewer can see shd-system-health
curl -sI "http://192.168.4.145:3001/d-solo/shd-system-health/system-health?orgId=1&panelId=1&kiosk" \
  | grep -i x-frame-options || echo "no X-Frame-Options (embedding allowed)"

# 3. summary query (exactly what "Build health query" sends)
curl -s --get http://192.168.4.145:9090/api/v1/query \
  --data-urlencode 'query=label_replace(count(up == 1), "stat", "targets_up", "", "") or label_replace(count(up), "stat", "targets_total", "", "")'

# 4. on the tablet
#    http://192.168.4.100:1880/ui/  → System Health tab:
#    - summary gauges show values within ~2s
#    - each embed card shows a Grafana panel within ~2-5s (lazy-loaded)
#    - no blank frames, no horizontal scroll at 800px
```

## Known gotchas

- **Blank iframes** (frame exists, `src` never loads) = `allow_embedding` not
  set on the Grafana server (check the `X-Frame-Options` header), or
  `GRAFANA_URL` unreachable from the tablet. An iframe with an EMPTY `src`
  attribute is a different failure — see the ng-src gotcha above.
- **"Datasource not found"** inside a frame = the provisioned dashboard lost
  its pinned datasource uid (`homelab-prom`) — see the provisioning gotcha in
  the homelab-metrics-stack skill.
- **Panels show "No data"** = the blackbox `blackbox-icmp` job or the `node`
  job is DOWN in Prometheus targets; work outward from the exporter, not from
  the panel (see the triage order in the homelab-metrics-stack skill).
- **Frame reloads every 60s** would tear down the Grafana SPA — it does NOT
  happen: the inject re-pushes an identical URL and the template's
  `scope.$watch` callback guards with `frame.getAttribute('src') !== url`, so
  same-value rewrites never touch the DOM. Grafana's own `refresh=30s` keeps
  the data moving.
- **Empty `src` on the iframes** = the template was still using Angular's
  `ng-src` (the pre-fix mechanism). In Angular 1.8 an iframe `src` is a `$sce`
  RESOURCE_URL context, and the dashboard's `uiTemplate` directive compiles
  the format **before** any message arrives (`scope.$watch(attrs.uiTemplate)`
  fires on link, when `innerScope.msg` is still undefined). The interpolation
  `{{msg.p.<key>}}` therefore evaluates to undefined, Angular strips the
  `src`/`ng-src` attributes from the DOM, and the binding never re-runs —
  measured live on 2026-10-12: all six frames rendered with no `src` and no
  `ng-src` attribute at all. The fix (shipped): the format's own `<script>`
  receives the live scope (`window.scope`, set by the directive around
  `element.html()`; jQuery 3.7.1 executes inline scripts) and assigns `src`
  imperatively from a `scope.$watch` on `msg.p.<key>`. Each iframe carries a
  static per-panel id (`shd-frame-<key>`) because jQuery's `DOMEval` runs the
  script from a temporary element in `<head>` — `document.currentScript`
  lookups cannot find the frame.
- **The `kioskHomeDashboard` feature toggle does not exist** — plain URL
  `kiosk` mode is all the embeds need.
